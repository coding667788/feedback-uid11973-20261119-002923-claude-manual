实现一个本地认证会话租约管理器，重点解决时钟回拨、会话续期与后台回收的并发一致性。账号身份已经由项目内的模拟前置组件确认，本题不实现密码校验、令牌交换或外部登录平台。环境为 Windows、Python 3.12 标准库和 SQLite，仅 CPU，不使用 Docker、真实外部服务。所有账号和时钟输入由你构造，不存在另行提供的附件。

一、会话按 tenant、account_id、session_id 隔离。创建时给定正整数 idle_ttl 和 hard_ttl，初始闲置到期点为 effective_now + idle_ttl，绝对到期点为 effective_now + hard_ttl；实际到期取两者较小值。会话仅在 effective_now 严格小于两个到期点且未注销时有效。touch 只能延长有效会话的闲置期限，更新为 min(hard_deadline, max(old_idle_deadline, effective_now + idle_ttl))，不能改变绝对期限，也不能恢复已过期或注销的会话。已使用的 session_id 在同一租户内不可重新创建，重启后也不能复用；同账号的其他会话不受单会话注销影响。

now 来自可注入的受信测试时钟，不是客户端自报时间，也不属于请求参数指纹。每个租户持久化一个逻辑时间水位。每次新的业务操作在取得数据库写事务后读取时钟和水位，effective_now = max(now, 水位)，并持久化新水位；业务拒绝也必须保留已前进的水位，已记录请求的幂等重放直接返回原结果而不重新采样时钟。不同租户水位独立。重启或输入时钟回拨不能使过期会话重新有效，等待数据库锁前读取的旧状态不能决定事务内结果。非法字段类型在进入业务操作前拒绝，布尔值不能冒充整数。

二、回收分为只读扫描和实际提交两个阶段。扫描列出在 scan_now 看来可能到期的会话及其版本，不推进时间水位，不改变状态；允许暂停扫描后，由其他进程续期、注销或推进水位。提交回收批次时必须在事务中重新读取当前状态，按本次受信 now 与当前水位重新判断，不能照着扫描快照直接删除。续期先提交且新期限仍有效时，旧回收批次不得误删；回收先提交后，迟到的 touch 必须失败。保留可查询的终止状态和原因，操作结果及状态变更原子持久化。每次 touch、logout、回收提交接受 request_id：同一租户内同号同参数恢复原结果，同号换参数返回 conflict；成功与业务失败都适用，返回丢失后的重试不能重复修改状态或重新采样业务时钟。

至少用三个独立进程共用数据库验证上述规则，正确性不能依赖进程内锁。用同步点固定“扫描—续期—回收”“扫描—回收—续期”和等待写锁期间水位变化的交错。真实终止自己启动的工作进程，分别覆盖事务提交前、提交后但结果未返回两处，再重启并重试，核对会话状态、水位与幂等结果。补充到期点相等、同租户与跨租户时钟回拨、失败请求换参、绝对期限不可延长等边界；预期结果由独立状态机计算，不能调用被测判断函数生成答案。

交付源代码、README、可重放样例及自动化测试，提供 python -m solution --input cases.json --output result.json 和 python -m unittest discover -s tests -v 两个入口。输入输出 schema、错误码、数据库初始化和 Windows 运行方式写清楚。测试必须断言具体状态和结果，并保留失败信息；所有操作只针对本机项目测试目录和本题自行创建的进程。
